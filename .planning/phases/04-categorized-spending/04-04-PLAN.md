<objective>
Deliver the CAT-05 run-rules-over-history path end-to-end (backend/API only — `UI hint: no`): a `RulesHistoryService` that sweeps the pure Plan 01 engine over ALL non-locked transactions (D-14), a `POST /api/rules/run/preview` endpoint returning the full diff (changed/overwritten/skipped-locked counts + per-row old→new changes) plus a staleness token (D-12/D-13), and a `POST /api/rules/run/commit` endpoint that recomputes the token from current state and applies the diff only on match, else returns 409 "stale — re-preview" (D-13). <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client → run/preview, run/commit | LAN/Tailscale caller triggers an account-wide recategorize and submits a previously-issued token; untrusted at the app boundary. |
| run/commit token → applied writes | The submitted token is a non-secret integrity tag; it gates whether the diff is written. A mismatch must block the write. |
| history sweep → transactions write-back | Only non-locked rows in the diff may be written; locked rows must be untouchable. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-4-stale | Tampering / lost-update | services/rules_history.py commit() | mitigate | Commit re-runs `_compute` and compares the freshly-recomputed sha256 token to the submitted one; mismatch → `StaleRunError` → HTTP 409, and NO `apply_categories` runs. Never blind-applies a preview-time diff (D-13 / Pitfall 4). `tests/test_history_preview_commit.py` proves the 409-on-stale case changes nothing. |
| T-4-lock | Tampering / data corruption | fetch_all_for_categorize + engine | mitigate | The account-wide sweep filters `WHERE NOT is_user_locked` in SQL AND the Plan 01 engine returns `_SKIP` for locked rows (defense-in-depth, D-09/CAT-04). The locked-row-unchanged assertion in the test enforces it; the frozen-by-omission upsert is the DB backstop. |
| T-4-eval | Elevation of Privilege / Tampering | predicate evaluation path | mitigate | No new evaluation path is introduced — the history sweep reuses the Plan 01 engine VERBATIM (D-11), whose closed-op `match` interpreter forbids `eval`/`exec`/`regex` (Pitfall 8). Acceptance grep confirms `rules_history.py` defines no matching logic of its own. |
| T-4-sqli | Tampering | transaction_repo.fetch_all_for_categorize | mitigate | Parameterized `text()`/ORM only; acceptance grep forbids f-string SQL. |
| T-4-SC | Tampering | npm/pip/uv installs | accept | Phase 4 installs zero new packages (RESEARCH §Package Legitimacy Audit — token uses stdlib `hashlib`/`json` only); no install task in this plan. |
</threat_model>
