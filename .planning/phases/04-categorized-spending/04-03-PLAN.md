<objective>
Wire auto-categorization into the import path (D-10/D-11): after `TransactionRepo.insert_many` returns the touched rows, a distinct categorize step loads the active priority-ordered rules and the touched **non-locked** rows, runs the pure engine from Plan 01 verbatim, and writes back `category_id` + `category_source='rule'` (NULL when no rule matches — D-02). Locked rows are filtered in SQL AND refused by the engine. This makes "zero manual upkeep" real: new transactions arrive already categorized.

Purpose: CAT-01 auto-application on import + the CAT-04 lock invariant (the headline must-pass test) on the import path. Establishes that the engine is reused verbatim (the same call the Plan 04 history sweep makes — D-11).

Output: Two new `TransactionRepo` methods, the import-service categorize step, and two green integration tests (`test_categorize_on_import.py`, `test_lock_invariant.py` for the import-step half).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Mono importer → categorize step | Newly-imported rows (untrusted external data) flow into categorization; must not overwrite user-locked intent. |
| categorize step → transactions write-back | Only non-locked touched rows may be written. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-4-lock | Tampering / lost-update | import_service categorize step + fetch_for_categorize | mitigate | `fetch_for_categorize` filters `NOT is_user_locked` in SQL AND the engine returns `_SKIP` for locked rows (defense-in-depth, D-09); plus the frozen-by-omission upsert can't clobber category columns. `tests/test_lock_invariant.py` proves a re-import leaves a locked row untouched (headline CAT-04 test). |
| T-4-bucket | Data integrity | apply_categories | mitigate | A no-match row is written `category_id = NULL` (D-02) — never silently bucketed into a real category. Asserted in test_categorize_on_import. |
| T-4-sqli | Tampering | transaction_repo new methods | mitigate | Parameterized `text()` / ORM only; acceptance grep forbids f-string SQL. |
| T-4-SC | Tampering | npm/pip/uv installs | accept | Zero new packages in Phase 4. No install task. |
